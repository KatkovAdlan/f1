# Журнал тестов XtoXray

## Как читать этот файл

Здесь фиксируются результаты запусков и проверок. Это не список планов и не история каждого файла. Для истории исходного кода используются Git-коммиты, для списка запланированных задач используется DEVELOPMENT_CHECKLIST.md, а для истории версий используется CHANGELOG.md.

## 28.09.2026

### Сборка
- Сборка локального проекта завершилась успешно.
- Собран JAR: xtoxray-1.0.0-neoforge.16.jar.
- Java: Microsoft OpenJDK 21.0.12.1 LTS.
- Minecraft: 1.21.1.

### Тестовая инстанция
- Использована отдельная инстанция XtoXray_Test.
- Базовая сборка: Gregnautics.
- Advanced XRay исключён из тестовой инстанции.
- Тестовый мир: XtoXray_TestWorld.

### Версия в GUI
- Предыдущая проблема: интерфейс продолжал показывать старую жёстко заданную версию .13.
- Исправление проверено в коде: GUI теперь получает версию из информации загруженного NeoForge-мода.

### Солнце и луна
- Предыдущий способ перехвата не сработал.
- Реализован перехват привязки текстур в LevelRenderer.renderSky().
- В ранней проверке пользователь счёл, что солнце и луна исчезают, но позже уточнил, что посмотрел недостаточно внимательно и фактически они оставались видимыми. Предыдущий подход с подменой текстур считается неуспешным.

### Автоматический вход в тестовый мир
- Первый способ через JoinWorldOnLaunch в реальном запуске пользователя не сработал.
- Добавлена тестовая Java-обёртка, которая получает launch script Pinecone и перед командой launch добавляет worldName XtoXray_TestWorld.
- После последнего исправления требуется отдельная проверка, что следующий запуск действительно открывает мир автоматически.

## Не подтверждено

- Автоматический вход в тестовый мир после последнего исправления ещё не зафиксирован как успешный тест.

## 29.09.2026 — прототип цветового X-Ray

### Что внесено
- Добавлен документ `COLOR_XRAY_DESIGN.md` с архитектурой отдельного цветового слоя.
- В `XrayState` добавлены настройки цветового режима и карта индивидуальных цветов блоков.
- Цвета сохраняются по идентификаторам блоков в `config/xtoxray.json`.
- Добавлен `ColorXrayRenderer` с кэшем результатов по чанкам.
- Добавлен предварительный рендер контуров выбранных блоков без проверки глубины.
- Добавлены отдельные render buffers для цветового слоя.
- Для первичного прототипа добавлена временная клавиша `C`.

### Как проверять вручную
1. Запустить `test.bat`.
2. В тестовом мире нажать `C`.
3. Проверить, появляются ли цветные контуры ванильных руд из белого списка через стены.
4. Проверить, что без `C` обычный мир остаётся без цветового слоя.
5. Проверить повторное нажатие `C` и возврат к обычному состоянию.

### Ожидаемый результат прототипа
- Цветовой режим включается независимо от обычного X-Ray.
- Цвет по умолчанию для блоков белого списка: бирюзовый.
- Отдельное скрытие обычных блоков и полноценное изменение цветов через GUI пока не подключены.

### Статус
- Код добавлен в ветку `feature/color-xray`.
- Локальная сборка этой ревизии пока не подтверждена.
- Проверка в `XtoXray_Test` пока не проведена.
- Пункты чек-листа цветового рендера не отмечаются выполненными до реального теста.

## 29.09.2026 — первая сборка прототипа

### Результат
- Сборка завершилась с ошибкой на этапе `compileJava`.
- Причина №1: использован неверный пакет `ChunkStatus`; в Minecraft 1.21.1 он находится в `net.minecraft.world.level.chunk.status`.
- Причина №2: результат `Level.getChunk(..., ChunkStatus.FULL, false)` не следует объявлять как `LevelChunk`; прототип переведён на вывод типа через `var`.
- Предупреждения о deprecated `EventBusSubscriber.bus()` сборку не ломали и пока не являются причиной отказа.

### Исправление
- Исправлен импорт `ChunkStatus`.
- Исправлен тип локальной переменной чанка в цветовом сканере.

### Статус
- Исправления внесены в ветку `feature/color-xray`.
- Повторная сборка после этих исправлений ещё не подтверждена.

## 29.09.2026 — полное отключение стандартного неба

### Исправление
- Предыдущий перехват `RenderSystem.setShaderTexture()` удалён как недостаточный: он затрагивал только отдельные текстуры.
- `LevelRenderer.renderSky()` теперь полностью отменяется при активном обычном X-Ray.
- Такой подход должен одновременно убрать фон неба, солнце, луну, звёзды и другие элементы, которые рисует сам `renderSky()`.

### Статус
- Код внесён в `feature/color-xray`.
- Результат в игре пока не подтверждён.


## 29.09.2026 — исправление тестового запуска

### Автоматический вход
- Выяснено, что Pinecone/Prism поддерживает штатный параметр `-w / --world` вместе с `-l / --launch` для запуска конкретного мира.
- Самодельная Java-обёртка больше не нужна и удалена из ветки.
- `test.bat` теперь запускает `XtoXray_Test` с `-w XtoXray_TestWorld` напрямую.

### Тестовый стенд
- Из `xtoxray_test_lab.js` удалено ограничение `worldborder`.
- Физическая арена и её стены пока сохранены, удалено именно ограничение дальности перемещения.

### Важное замечание по Advanced XRay
- В добавленном в основной репозиторий архиве Advanced XRay 21.0.0 `xray.mixins.json` содержит только `ClientDestroyBlockEvent`.
- В доступном исходном коде Advanced XRay отдельной логики для `renderSky()` не обнаружено.
- Его текущая архитектура действительно использует отдельный кэш найденных блоков и собственный рендер контура после погодного этапа, но скрытие неба нашим модом приходится реализовывать отдельно.

### Статус
- Штатный запуск мира после изменения ещё не подтверждён реальным запуском пользователя.
